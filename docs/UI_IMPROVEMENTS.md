# UI 改善方案

> 基于 2026-08 对当前代码（`options/options.html`、`options/options.css`、`options/options.js`、`content/content.js`）的 UI 审视整理，行号以当时代码为准，可能随迭代漂移。
>
> 总体底子较好：抖音暗色风格统一、CSS 变量体系完整、虚拟化网格/骨架屏/媒体熔断等性能细节到位、危险操作均有"不可撤销"确认文案、长任务弹窗 X 始终可点以发送取消信号、详情层有完整键盘导航。本文只记录待改善项。

## 一、反馈与确认流

### 1. Toast 单一无形态

**问题**：`Dialog.showToast`（`options/options.js` 约 :808）只有一种样式，成功和错误提示长得一样；时长固定 `TOAST_DURATION` 2 秒；`.toast` 的 `white-space: nowrap`（`options/options.css` 约 :1413）会让长错误文本横向溢出屏幕。"下载失败: …"、"取消失败: 可能是密钥已过期…"这类信息 2 秒内读不完。

**方案**：
- `showToast(message, type)` 增加 success / error / info 三型，视觉上左侧色条或前缀图标即可，不必大改；
- error 型时长提到 4–5s；
- 去掉 `nowrap`，加 `max-width: 80vw` 允许换行。

### 2. 终态确认屏多一次点击（执行期弹窗保留）

**问题**："移除完成 → 已移除该作品 → 好的"（`Detail` 移除流程，约 :3796），批量删除、批量移动、重置同款。

**设计约束（须遵守）**：弹窗在长耗时操作的**执行期**承担模态保护——spinner + `state.preventDialogClose` 挡住底层大规模 UI 变化（批量删除/移动会触发虚拟网格批量卸载重排），防止用户中途误操作。这层保护不能削弱，toast 只用于短操作。

**方案**：只改执行完成后的**终态确认屏**——此刻 UI 变更已全部落定（`grid.removeItems` 在 await 返回前已执行），风险窗口已关闭：
- 操作成功且结果简单时，跳过"好的"屏，自动关闭弹窗，以带计数的 success toast 收尾（如"已移除 120 个作品"）；依赖建议 1 的分型 toast 先落地；
- 保留终态弹窗的例外：导入结果（多行统计需要阅读）、部分失败（失败数需要核对）、整域重置（高破坏性，显式终点有心理价值）、完成后仍需用户决策的场景。

### 3. 弹窗不支持 Esc 关闭、无焦点管理

**问题**：详情层有完整键盘支持（Esc / ↑↓ / ←→，`options.js:3740`），但 `#dialogOverlay` 只能点 X 关闭；弹窗打开时焦点不移入、关闭后不还原；无 `role="dialog"` / `aria-modal`。

**方案**：
- dialog 层监听 keydown Esc，须尊重现有 `state.preventDialogClose` 锁与长任务"X 发送取消信号"语义；
- 打开时把焦点移入弹窗第一个可交互元素，关闭后还原到触发元素；
- 补 `role="dialog"` / `aria-modal="true"`。

### 4. 批量模式没有选中计数

**问题**：进入批量模式后看不到已选几条；「移动」「移除」在未选中时点击走静默 `return`（`Batch.handleBatchDelete` 约 :1323），用户会以为功能坏了。

**方案**：顶栏（或全选按钮旁）常驻显示"已选 N"；N=0 时两个按钮置 `disabled`，消除状态盲区。

## 二、检索能力

### 5. 几千条数据没有任何检索手段

**问题**：作品库只有分组一个维度，找某个作品只能肉眼翻页。数据结构上作者、标题、类型、播放量都已入库，完全支持检索。

**布局约束（须遵守）**：顶栏已有域切换、分组 tab、批量按钮组、菜单四组元素，**不得新增常驻搜索框/工具条**，否则交互元素过密。

**方案**：
- topbar-right 增加一个筛选图标按钮（ghost 样式，与现有按钮同级），点击弹出锚定 popover——复用 `menu-dropdown` 的定位与"点外关闭"模式，不新增常驻布局区域；
- popover 内含：搜索输入框（防抖，匹配标题 / 作者昵称 / awemeId；关注域下匹配昵称）、排序切换（最新 / 最旧 / 播放量）、类型筛选（视频 / 图集）；
- 有筛选生效时按钮显示激活标记（主题色圆点），提示当前视图非全量；
- 支持 `Ctrl+K` 或 `/` 唤起并聚焦输入框，`Esc` 关闭（详情层已有键盘导航先例）。

实现约束：过滤在 `renderCards()` 之前对数据数组做（或引入独立的 filtered 视图数组），**不动 VirtualGrid 本身**，避免触碰分圈观察、填充/卸载交接等既有性能设计。

## 三、详情覆盖层

### 6. 图片左右导航按钮定位脆弱

**问题**：`.detail-nav-btn:last-child` 靠 DOM 顺序定位右侧按钮（`options.css:1172`），HTML 结构一变即坏；且 left 16px / right 12px 不对称，疑似笔误。

**方案**：给右导航独立类名（如 `.detail-nav-right`）显式定位，同时修正间距对称性。

## 四、可访问性与一致性

### 7. 可达性欠账

**问题**：
- 勾选圆是 div，无 `role="checkbox"` / `aria-checked` / 键盘支持（模板见 `options.html:214`、`:155`）;
- 图标按钮大多只有 `title` 没有 `aria-label`；
- 全局没有 `:focus-visible` 样式，键盘操作看不到焦点位置；
- 卡片不可 Tab 聚焦，无法用键盘打开详情。

**方案**：属性级修补，不碰逻辑——勾选圆补 role/aria-checked/aria-label 并响应 Enter/Space；图标按钮补 aria-label；全局定义 `:focus-visible` 轮廓；卡片根节点加 `tabindex="0"` + Enter 打开详情（VirtualGrid 已是事件委托模式，成本低）。

### 8. 术语混用

**问题**：批量操作的确认标题是「确认删除」、正文"确定删除选中的 N 个作品"、执行按钮却是「移除」（`options.js:1331` 附近）；分组操作叫「删除」、整域操作叫「清空」。同一动作三种叫法。

**方案**：定动词表并贯彻——库内条目 = **移除**、分组 = **删除**、整域 = **清空**；批量确认弹窗标题/正文统一为「移除」。

### 9. 模板小瑕疵

**问题**：
- 分组管理列表项中删除图标 `width=24` 而重命名图标 `width=14`（`options.html:253-260`），尺寸不一致；
- 设置面板运行参数的 min>max 校验滞后到保存才 toast 报错（约 :2611），输入时无即时反馈，也没有「恢复默认」入口。

**方案**：统一两个操作图标尺寸；min/max 输入改为输入时红框即时提示；运行参数区加「恢复默认」按钮（默认值来源即 background `CONFIG.DELAY/SYNC/TIMEOUT` 的初始值）。

## 建议实施顺序

| 批次 | 条目 | 理由 |
|------|------|------|
| 第一批 | 1、3、4、6、8、9 | 小改动，日常使用感知强 |
| 第二批 | 2、7 | 中等改动，涉及交互流调整 |
| 第三批 | 5 | 结构性最强（搜索/排序/筛选），需先定过滤层方案再动手 |

> 实施时注意遵守 AGENTS.md 的代码布局规范与既有性能约定（VirtualGrid 不换根节点、媒体槽位 div+background-image、探针代际校验等均不受本方案影响）。
